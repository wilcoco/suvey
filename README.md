# 협력사 거래·소통 실태 설문 (무기명)

협력사 대상 무기명 설문 웹앱입니다. Node.js(Express) 단일 서버로 설문 페이지, 결과 대시보드, 저장을 모두 처리합니다.

## 구성

| 경로 | 용도 |
|---|---|
| `/` | 설문 응답 페이지 (모바일 우선, 한 문항씩 탭하면 자동 진행) |
| `/admin` | 결과 대시보드 (관리자 키 필요, 대표이사 전용) |
| `/api/admin/csv` | 응답 원본 CSV 다운로드 (관리자 키 필요) |

문항은 `questions.js`에서 수정합니다. A파트 10문항(행동 빈도) · B파트 3문항(5점 척도) · C파트 3문항(비교 1 + 서술 2) · 응답자 구분 1문항(선택).

## 자동 진단

각 문항의 의도를 9개 문제 유형(서면화 부재, 일방적 변경, 비용 전가, 응답 부재, 창구 혼선, 책임 전가, 고압적 태도, 침묵, 경청 부족)에 매핑해두고, 응답 분포가 임계치를 넘으면 유형별로 **양호/주의/심각**을 판정하고 미리 준비된 개선책을 관리자 화면에 표시합니다.

- 판정 기준: 빈도 문항은 발생률 20%↑ 주의, 발생률 50%↑ 또는 "여러 번" 30%↑ 심각 / 척도 문항은 부정률 20%↑ 주의, 40%↑ 심각
- 교차 신호: 응답 솔직도 의심(A10 패턴), 타 고객사 대비 열위(C1), 경영진-현장 응답 격차(R1)
- 유형 정의·임계치·개선책은 전부 `diagnosis.js` 한 파일에서 수정합니다

## 익명성 보장 장치

- 이름·회사명·연락처 등 식별 정보를 아예 수집하지 않음
- IP·User-Agent 등 접속 정보를 저장하지 않음 (접속 로거 미사용)
- 제출 시각은 **날짜 단위까지만** 저장 (시각으로 응답자 추정 방지)
- 개별 응답 열람은 `ADMIN_KEY`를 가진 사람(대표이사)만 가능

## 로컬 실행

```bash
npm install
ADMIN_KEY=원하는키 npm start
# http://localhost:3000
```

## Railway 배포

1. 이 저장소를 GitHub에 push한 뒤 Railway에서 **New Project → Deploy from GitHub repo** 선택
2. 빌드 설정은 자동 감지됩니다 (`npm start`)
3. **Variables**에 환경변수 추가:
   - `ADMIN_KEY` — 관리자(대표) 열람용 키. **반드시 설정** (미설정 시 결과 열람 불가)
   - `COMPANY_NAME` — 문항에 표시할 회사명 (기본값 `CAMS`)
   - `DATA_DIR` — `/data` 로 설정
4. **응답 데이터 보존을 위해 볼륨 필수**: 서비스 → Settings → **Volumes → Add Volume**, Mount Path를 `/data`로 지정.
   볼륨 없이 배포하면 재배포 때마다 응답이 사라집니다.
5. Settings → Networking → **Generate Domain**으로 공개 URL 생성 후, 그 URL을 협력사에 배포

## 환경변수 정리

| 변수 | 필수 | 설명 |
|---|---|---|
| `ADMIN_KEY` | O | `/admin` 결과 열람 키 |
| `COMPANY_NAME` | X | 문항 내 회사명 (기본 `CAMS`) |
| `DATA_DIR` | X | 응답 저장 경로 (Railway는 `/data` 권장) |
| `PORT` | X | Railway가 자동 주입 |

## 운영 권고 (설문 설계 배경)

- A10(불이익 우려로 침묵) 문항은 응답 솔직도의 온도계 — 결과 해석 시 이 문항부터 볼 것
- 서술형 원문은 사내에 그대로 공유하지 말고 유형화해서 전달할 것 (응답자 색출 방지)
- 반기 1회 정례화하고, 매회 "지난 설문 지적 → 조치한 것"을 안내와 함께 보낼 것
